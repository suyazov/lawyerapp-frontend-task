# LawyerApp

Веб-приложение «история правок юридических документов с ответственностью».
Концепция, модель данных и спека — в командной вики `team-wiki/LawyerApp/`.

## Тестовое задание: Mini CRM для юриста

В проект добавлен рабочий прототип мини-CRM для сценария, где юрист ведёт клиентов.

Страница: `/clients`

Сценарий реализован:

1. Юрист открывает страницу с дашбордом клиентов.
2. Видит таблицу со списком клиентов.
3. Может добавить клиента: имя, телефон, статус дела.
4. Может изменить статус клиента: `Новый` → `В работе` → `Закрыт`.
5. Видит счетчики клиентов по каждому статусу.

Дополнительно:

- есть демо-клиенты при первом запуске;
- данные сохраняются в `localStorage` браузера;
- можно удалить клиента;
- можно вернуть демо-данные;
- страница добавлена в боковое меню как `Клиенты`;
- интерфейс адаптирован под текущий стиль LawyerApp.

Для быстрого MVP выбран `localStorage`, чтобы показать рабочую продуктовую механику без настройки бэкенда. В production-версии хранение клиентов логично вынести в Supabase/PostgreSQL или API проекта, добавить авторизацию юриста, роли, историю изменений и уведомления.

## Стек

Next.js 16 · React 19 · TypeScript · Tailwind CSS 4 · shadcn/ui (base-nova, baseColor neutral) · lucide-react · sonner.

## Запуск

```bash
npm install
npm run dev      # http://localhost:3000
# или прод
npm run build && npm run start
```

## Что внутри (пока на мок-данных)

- **Реестр договоров** (`/`) — поиск, фильтр по сумме с переключателем валют (₽/$/€/¥, окно ±шаг), фильтр по менеджеру и статусу, быстрые фильтры «Блокеры»/«Просрочка», сортировка (по №/дороже/дешевле), сводка портфеля.
- **Mini CRM для юриста** (`/clients`) — список клиентов, добавление клиента, смена статуса дела, счетчики по статусам, сохранение в localStorage.
- **Страница проекта** (`/projects/[id]`) — реквизиты + документы пакета.
- **Таймлайн документа** (`/documents/[id]`) — сворачиваемые дни со статусом дня, сайд-бай-сайд дифф на уровне пункта, **уровень решения** (можно самим / ответственный / блокер·командой), детект конфликтов, карточка-ЗРС с решением (для блокеров — «Эскалировать команде»).
- **Как видит Claude** (`/agent`) — демо agent-слоя (get_state / resolve_document / prepare_next_version).

## Структура

```
src/app/clients/page.tsx     — страница Mini CRM
src/components/clients-crm.tsx — клиентский CRM-компонент
src/lib/nav.ts               — пункты боковой навигации
src/lib/types.ts             — доменные типы
src/lib/domain.ts            — справочники (статусы/уровни/валюты) + хелперы (money, dayStatus, …)
src/lib/fixtures.ts          — мок-данные за доменным слоем
src/components/*-view.tsx    — экраны (registry / project / timeline / agent)
src/components/ui/*          — shadcn-компоненты
reference/prototype.html     — исходный кликабельный HTML-прототип (референс дизайна)
```

Данные временно мок (`src/lib/fixtures.ts`). Бэкенд (API + БД) — зона Эдема; предлагаемый контракт типов/эндпоинтов — в вики (`api-contract.md`). Мок-слой устроен так, чтобы позже подменить его на реальный API-клиент без переделки экранов.

## Лог по AI-first доработке

- Самостоятельно определил продуктовый сценарий мини-CRM и встроил его в существующий LegalTech-интерфейс.
- AI использовался как ускоритель разработки: структура компонента, варианты UI, проверка логики состояния и формулировки README.
- Для тестового задания выбран быстрый стек внутри существующего проекта: Next.js + React + localStorage. Это позволило показать рабочую механику за короткое время без отдельного сервера и базы данных.
