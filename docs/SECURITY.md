# Security notes — LawyerApp (frontend task)

Это frontend-тестовое на мок-данных. В репозитории **нет секретов, авторизации, backend и реальных интеграций**.

## Что проверено

- **Нет секретов:** `.env` файлы отсутствуют, в коде нет API-ключей, паролей, токенов.
- **Мок-данные:** все пользователи, проекты, документы и правки — фикстуры в `src/lib/fixtures.ts`. Никакие реальные контрагенты или суммы не используются.
- **Нет auth/backend:** экран работает целиком на клиенте, локальном `useState` и мок-данных.
- **Внешние ссылки — заглушки:** ссылки на Битрикс (`https://bitrix.example/...`) ведут на несуществующий домен `example` и служат только визуальным маркерам.
- **Загрузка файлов — демо:** диалог «Собрать новую версию» не отправляет файлы на сервер, а только обновляет локальный массив версий.
- **Зависимости:** `npm audit --audit-level=moderate` на момент сдачи показывает 2 moderate advisory в транзитивном `postcss`, который приходит через `next@16.2.9`. `npm audit fix --force` предлагает breaking-change откат до старой ветки Next, поэтому для тестового задания зависимость оставлена как есть. Перед продакшеном стоит обновить Next.js, когда выйдет совместимый патч.

## Что сознательно вне скоупа

- Аутентификация и авторизация.
- Серверная валидация загружаемых документов.
- Хранение данных в базе / API.
- CSP, rate-limiting, CORS.

## Рекомендации перед реальным запуском

1. Вынести fixtures в backend с авторизацией по ролям.
2. Валидировать загружаемые файлы на сервере (тип, размер, скан на вирусы).
3. Заменить `bitrix.example` на реальные интеграции с проверкой URL.
4. Добавить CSP и защиту от XSS для рендеринга пользовательского контента.
5. Регулярно обновлять зависимости и пересматривать `npm audit`.
